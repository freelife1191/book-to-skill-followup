## 증거의 종류

실행 기록에서는 증거를 다음처럼 구분합니다.

| 증거 | 증명하는 것 | 증명하지 않는 것 |
|---|---|---|
| 실제 도구·CLI 로그 | 명령이 실행됐고 그 로그에 나타난 작업 | 평가자가 읽은 모든 문서나 내용의 정확성 |
| 평가자의 읽기 목록 | 평가자가 보고한 자료 범위 | 실제 도구 명령이 같은 순서로 실행됐다는 사실 |
| 같은 평가자의 재생성 | 수정 후 같은 조건에서 응답이 달라진 결과 | 새 독립 세션의 재검증 |
| 새 독립 평가 | 이전 결론을 모르는 별도 평가의 판정 | 전체 프롬프트·모든 환경의 보증 |
| 수동 기록 정정 | 기록의 경로·해시·메타데이터 보정 | 행동 답변의 재실행이나 도구 로그의 대체 |

초기 실패 기록은 보존합니다. 최종 기록은 실패가 있었던 사실과 어떤 종류의 재검증을 거쳤는지 함께 적습니다.

## 정적 검사

`check_package.py`는 대상 프로젝트의 파일 구조, 링크·앵커, 해시·경로, 문서와 역할 프로필의 배치를 검사합니다. **Python 3.11 이상**, `PyYAML`, `markdown-it-py`가 필요합니다. 이 프로젝트를 제작·검수한 현재 환경에는 두 파서가 있었지만, 대상 실행 환경까지 보장하지는 않습니다. 필요한 도구가 없으면 자동으로 설치하지 않고 `blocked`를 기록합니다.

생성된 책 대상에서는 `book-to-skill-followup` 제작 스킬과 별칭의 혼입도 검사합니다. 대상 지식 안의 복사본은 실패하며, 프로젝트의 로컬 설치는 Git index와 명시적 제외 상태를 구분합니다. 원본 도구 자체를 검사하는 경우와 과거 문서의 단순 이름 언급은 혼입으로 취급하지 않습니다. 실제 아카이브·전역 설치 전체까지 검사하는 것은 아닙니다. [배포 분리와 검사 범위](../.agents/skills/book-to-skill-followup/references/packaging.md)를 참고하세요.

```bash
python3 -B "$FOLLOWUP_SKILL_DIR/scripts/check_package.py" \
  --project /absolute/path/to/project \
  --skill .agents/skills/my-book-skill \
  --documents README.md \
  --documents docs \
  --run-dir /absolute/path/to/run \
  --output /absolute/path/to/run/coordinator/static-checks.json
```

정적 통과는 링크와 구조가 현재 검사 범위에서 유효하다는 뜻입니다. Markdown 알림 블록의 실제 UI 렌더링, 원문 해석의 정확성, 호스트에서의 스킬 선택은 별도 검사 대상입니다.

목차·장별 프롬프트 바로가기는 표시 텍스트도 별도로 검토합니다. 예시와 후속 요청의 실제 제목이 드러나는지, 목적지 제목과 일치하는지, 긴 제목이 목록·표에서 읽기 쉽게 배치됐는지 확인합니다. 이 검토를 링크·앵커 자동 검사의 결과로 대신하지 않습니다. 구체적인 기준은 [프롬프트 제목과 바로가기](../.agents/skills/book-to-skill-followup/references/documentation.md#프롬프트-제목과-바로가기)를 참고합니다.

## 원문 검수 체크리스트

- [ ] 모든 장·주제에 스킬 반영 위치 또는 누락 사유가 있다.
- [ ] 세부 기법·성립 조건·예외·대조 사례를 실제 대응 문장과 비교했다.
- [ ] 제목·링크·claim 개수만으로 내용 충실도를 통과시키지 않았다.
- [ ] 직접 설명, 재구성, 검증 기반 적용 지침, 새 프로젝트 제안을 구분했다.
- [ ] 책의 사례값을 기본 정책으로 고정하지 않았다.
- [ ] 미정·모순은 위치·영향·결정 질문으로 남겼다.
- [ ] 정책의 적용 범위와 다른 미정 축, 실제 상태와 도입할 기능을 구분했다.
- [ ] 원문 용법·일반 정의·저자와 편집자의 귀속, 수치의 시작점·단위를 확인했다.
- [ ] PDF와 인쇄 쪽수의 대응을 해당 원문에서 확인했다.
- [ ] 판단을 바꾸는 저자의 주장·조건·수치·예외 문장에 원문 형식에 맞는 위치가 있다. 인쇄 쪽수와 PDF 인덱스가 다르면 위치 쌍을 쪽 대응표로 기계 대조했다.
- [ ] 새로 붙이거나 바꾼 위치를 새 컨텍스트의 source-reviewer가 표본 대조했고, 전체 수·대조 수·표본 수를 따로 기록했다.
- [ ] 조건의 결합·강도·기준·시점이 원문과 같은지 원문의 해당 문장으로 확인했다.
- [ ] 귀속을 두 방향(스킬 정리→저자, 저자 절차→스킬 양식)으로 원문의 해당 쪽에서 확인했다.
- [ ] 대상 SKILL.md가 답변 근거 범위·파일 전체 읽기·귀속 표시를 답변 모델에게 알려 준다. 기준이 불명확한 수치처럼 책에 따라 달라지는 지침은 해당할 때만 넣었다.
- [ ] 대상 SKILL.md 본문에 Claude Code가 불러올 때 바꿔 쓰는 표기(`$1`, `$ARGUMENTS`, `${CLAUDE_SKILL_DIR}`, `` !`명령` ``)가 없다.
- [ ] 주장에 직접 쓰인 표·그림과 의심 항목의 후보·실제 표본을 기록했다.

`source-audit`의 `pass`는 검수 범위와 finding의 기록 품질에 대한 판정입니다. 원문과 스킬이 어긋난 `mismatch`·`needs-refinement` finding이 있어도 보완 단계로 진행할 수 있습니다. 원문을 읽지 못했거나 인벤토리 단위를 검수하지 못하면 `blocked`이며, 중요한 finding을 해결하지 못하면 최종 `freeze`는 통과할 수 없습니다.

> [!WARNING]
> “모든 장이 있다”는 결과는 스킬 자료의 대응 범위를 뜻합니다. 원문의 모든 문장·도표를 재현하거나 전수 시각 검증했다는 주장이 아닙니다.

## 독립 행동 시험 체크리스트

- [ ] 자료 선택·개념 확인, 실제 적용, 모순·미정 검토의 대표 사례 3개가 있다.
- [ ] 발견된 결함마다 재현 입력·필수 결과·금지 결과가 있는 회귀 사례가 있다.
- [ ] 평가자가 예상 답변과 이전 결론을 받지 않았다.
- [ ] 통과는 키워드 일치가 아니라 의미·행동 기준으로 판정했다.
- [ ] 수정 뒤 최종 통과 근거에는 새 독립 평가가 포함돼 있다.
- [ ] 보강 조건을 사용하는 대표 예시·후속에서 판정·근거·미확인 항목이 이어진다.
- [ ] 새 대화용 후속은 채워진 요청만 받은 다른 새 컨텍스트에서 확인했다.
- [ ] 전체 문서의 정적 검토와 실제 실행한 case의 통과 범위를 구분했다.
- [ ] 대표 요청 일부를 host-smoke와 같은 격리 인자로 사용 호스트 CLI의 새 세션에서 실행하고, 원래 로그에서 스킬 로드·스킬 폴더 밖 접근·부분 읽기·위치 인용을 확인했다. 격리할 수 없는 호스트는 한계로 기록했다.
- [ ] 명시 호출과 스킬 이름 없는 자연어 요청을 나눠 시험했다. Claude `-p`의 slash 요청은 '로드 미관측'으로 기록했다.
- [ ] 판정자는 귀속·정확성 항목을 원문의 해당 쪽으로 판정했고, 귀속을 전제한 rubric 항목도 원문으로 확인했다.

같은 평가자의 재생성은 유용한 확인이지만, 새 독립 평가로 이름을 바꾸지 않습니다.

## 한국어 마지막 검수

`improvement` 뒤 `freeze` 전에 vendored DaleSeo/korean-skills의 `humanizer → grammar-checker → style-guide`를 이 순서로 실제 읽어 적용합니다. 현재 subject의 Markdown·JSON·YAML을 빠짐없이 path/SHA-256으로 기록하고, 어색한 문장·맞춤법·띄어쓰기·문법·구두점·용어와 문서 스타일을 문맥으로 검토합니다. 단순 파일 존재나 자동 정규식만으로 이 검수를 통과로 표시하지 않습니다.

통과 기록에는 제작자와 다른 reviewer, 세 upstream 스킬의 실제 경로·SHA-256·commit, 별도의 사람 또는 에이전트 검토 기록을 포함합니다. 조건·수치·인용·부정·기간·귀속은 모두 true로 보존을 확인해야 합니다. 영어 source, 원문 제목, 코드, 주식 전문 용어는 문맥상 적절하면 보존하며 humanizer의 추정 AUC를 이번 문장 검수 점수로 표현하지 않습니다. 상세 스키마는 [한국어 마지막 검수 계약](../.agents/skills/book-to-skill-followup/references/language-review.md)을 따릅니다.

보조기는 vendor tree·파일 해시·세 단계의 검토 기록·읽기 manifest·reviewer와 fresh dispatch 기록의 구조를 검사합니다. Codex는 native `fork_turns: none`, Claude와 Antigravity는 같은 호스트의 fresh native context와 session ID를 기록합니다. 이 구조 검사는 실제 독립성, 문장의 어색함, 또는 의미 보존을 자동으로 증명하지 않습니다. 실제 검토자가 문맥과 세 단계 결과를 읽어 판정하며, 단위 fixture는 그 구조를 검증하는 mock입니다.

보정이 필요하면 `freeze` 전 `revise --from-stage documentation`으로 관련 정적·행동 시험을 stale로 만든 뒤 새 증거로 다시 진행합니다. `freeze` 뒤에는 새 run을 시작합니다.

## 최종 호스트 검사

메인 에이전트가 고정된 복사본을 사용 중인 호스트에서 실제로 호출합니다. `host_smoke.py`는 호스트별 어댑터를 통해 격리 복사·실행 기록·스킬 로드 추적을 수집하는 보조기입니다. 임의의 셸 명령이나 원문 속 명령을 실행 대상으로 삼지 않습니다.

```bash
python3 -B "$FOLLOWUP_SKILL_DIR/scripts/host_smoke.py" \
  --run-dir /absolute/path/to/run \
  --prompt coordinator/host-prompt.txt
```

실제 호스트 호출 방식과 필요한 증거는 `references/host-adapters.md`의 해당 호스트 계약을 따릅니다. 안전한 어댑터·추적이 없으면 이 단계를 `blocked`로 기록합니다.

호스트 버전은 메인 에이전트가 별도로 확인해 실행 기록에 저장합니다. 예를 들어 Codex에서는 최종 호출 전에 다음과 같이 기록합니다. 버전 확인 명령은 모델 호출 횟수에 포함되지 않습니다.

```bash
codex --version > "$FOLLOWUP_RUN_DIR/coordinator/host-version.txt" 2>&1
```

Claude Code에서는 `claude --version`을 사용합니다. Antigravity는 실제 사용하는 앱·CLI의 버전 정보를 기록합니다. 확인할 수 없으면 확인 불가 이유를 적고, 이전 관측값을 현재 버전으로 가정하지 않습니다.

검사 기록에는 호스트·버전·실행 인자, 고정 전후 해시, 프롬프트, 종료 상태, 관련 로그 경로, 확인한 한계를 포함합니다. 사용하지 않은 호스트는 정적 배치 검사만 했다고 적습니다.

> [!IMPORTANT]
> 호스트 호출 뒤 스킬·문서·프롬프트·검사 기준을 고치면 고정본이 아니므로 그 호출은 최종 통과 근거가 될 수 없습니다. 새 실행에서 다시 진행합니다.

## 완료 판정

다음 모두 충족할 때만 완료입니다.

1. 원문 검수와 출처 구분 기록이 있다.
2. 정적 검사와 독립 행동 시험이 기준을 충족한다.
3. 최종 결과물의 해시가 고정돼 있다.
4. 사용 중인 호스트에서 그 고정본을 한 번 실제 호출했다.
5. `release-reviewer`가 증거와 한계를 함께 판정했다.

필수 조건이 빠지면 완료라고 표현하지 않고 차단된 단계와 다음에 필요한 조건을 기록합니다.

## 제작 검증 결과

2026-10-12에 Python 3.14.8과 Codex CLI 0.162.0 환경에서 확인했습니다. **최종 수용 실행 C는 당시 `verify`와 `finalize`까지 통과**했습니다. 이 기록은 이후 추가된 한국어 마지막 검수 도구 체인으로 재검증된 결과가 아니며, 그 검수는 새 run에서 수행해야 합니다.

|---|---|---|
| 단위 시험 | 상태·해시·경로·재개·무효화·호스트 로그·실제 정적 검사 연동 | 26건 통과 |
| 스킬·FLOW 형식 | skill-creator 검증기, harness 명세 검증기, Python 구문 검사 | 통과 |
| 짧은 원문 수용 시험 | 자체 작성한 원문 3개 주제의 검수·레퍼런스·문서·시험·최종 판정 | 전체 FLOW 통과 |

후속 스킬은 메인 네이티브 에이전트가 지침을 따라 수행했고, 실제 CLI의 마지막 호출은 **완성된 지식 스킬**을 대상으로 했습니다. 후속 스킬 자체를 재귀 CLI 호출하는 시험은 하지 않았습니다. 유리링 전자책의 21장을 이번 제작에서 다시 전수 검수한 결과도 아닙니다.

### 실패 기록에서 반영한 수정

- **A 실행:** 바깥 실행 도구의 세션 ID를 보존하지 않아 호스트 결과를 확보하지 못했습니다. 실행 중 로그를 파일에 저장하고 세션을 이어 확인하도록 보완했습니다.

## 교차 호스트 실제 진입 시험

같은 2026-10-12에 별도 프로젝트와 실행 ID로 **후속 스킬 자체**를 실제 호출했습니다. 범위는 읽기 전용 입력·원문 대응·예비 내용 검토이며, 상태 파일 작성·보완 편집·독립 하위 에이전트·최종 지식 스킬 호출을 포함한 전체 FLOW를 다시 수행한 시험은 아닙니다.

| 호스트 | 실제 관측 | 판정 범위 |
|---|---|---|
| Claude Code 2.1.296 | init에서 스킬과 역할 세 개를 발견했지만 OAuth 만료·갱신 실패, exit 1 | 인증 차단; 사용자 요청으로 추가 호출 생략 |
| AGY CLI 1.3.3 | init expanded_commands에 실제 skill 확장, view_file로 원문·자료·공통 검수 계약 탐색, SUCCESS와 exit 0 | 읽기 전용 예비 호출을 수행; 의미 검토는 종료와 별도로 판정 |

### 발견한 문제와 보완

1. **stdout 스키마:** 실제 AGY는 `event: init/step_update/result`, `parameters.AbsolutePath`, ACTIVE/DONE을 사용합니다. 기존 단순 tool_use/tool_result 가정에서 이 원래 스키마를 추가로 처리하도록 수정했습니다.
2. **거짓 성공:** 여러 conversation·충돌 단계·ERROR 뒤 DONE·비어 있거나 비문자열 출력은 읽기 증거로 인정하지 않습니다. 단일 init/result와 같은 대화·단계·경로를 결속하고 native/legacy 형식을 섞지 않습니다.
3. **Claude 결과 처리:** 공식 성공 tool_result처럼 is_error가 생략된 결과도 요청 ID·내용과 연결합니다. 반대로 OAuth 오류의 result.is_error가 true이면 subtype이 success여도 완료로 인정하지 않습니다.
4. **대응과 반영의 혼동:** 대응 파일이 있는 것과 원문 핵심 요소가 실제로 들어 있는 것을 구분하도록 지침을 보완했습니다. 예비 검토에서도 원문 검수 레퍼런스를 먼저 읽도록 연결했습니다.
5. **근거 없는 부재 단정:** 실제 목록·검색·명확한 파일 없음 오류를 확인하지 않았다면 링크 대상을 없다고 단정하지 않고 미확인으로 남깁니다. 권한 오류와 부재를 구분합니다.

첫 호출의 독립 사후 검토는 통과했지만 후속 새 호출에서 내용 대응과 부재 증거 문제가 드러났습니다. 해당 실패를 삭제하지 않고 지침을 두 번 보완한 뒤 새 conversation에서 재시험했습니다. **사후 의미 검토를 사전등록 시험으로 이름 바꾸지 않았습니다.** 같은 검토자의 재검토, 새 독립 검토, 원래 로그의 새 검사기 재생 검증을 구분했습니다.

### 최신 검증과 한계

단위 시험 **30건**, 독립 코드 재리뷰, 마지막 실제 호출의 **새 독립 사후 의미 검토 8개 항목**이 통과했습니다. 마지막 호출은 정상 종료했고 view_file 성공 7건과 파일 부재 오류 3건을 확인했습니다. 부재 오류는 확인하려던 누락의 근거이며, 검토 자체의 실패로 숨기거나 모든 도구가 성공한 것으로 바꾸지 않았습니다. 대상·원문·설치된 시험 스킬 파일은 변경되지 않았습니다.

Antigravity는 서로 다른 프로젝트·conversation에서 총 4회 호출했습니다. 최초 통과와 중간 실패 2회, 보완 후 통과를 모두 보존했습니다. Claude Code는 1회 시도 후 인증 차단됐고 추가 호출하지 않았습니다. 원시 로그·실패·정정·검사기 해시는 로컬 `output/host-acceptance/2026-10-12/`에 보존하고 배포 자료에서 제외합니다.

> [!IMPORTANT]
> 실제 slash 확장과 view_file 읽기를 구분합니다. SUCCESS/exit 0은 답변 정확성이나 모든 도구 성공을 보장하지 않습니다. plan/sandbox 옵션만으로 모든 파일 도구·MCP가 읽기 전용이라고 주장하지 않으며, 이번 시험은 실제 사용 도구와 대상 파일의 변경 여부로 범위를 확인합니다.

GUI·전체 Claude/Antigravity FLOW·Antigravity 역할 프로필의 실제 선택/독립 실행·모든 책과 요청 조합은 미검증입니다. 전체 FLOW 필수 게이트는 이 제한된 시험의 통과로 대체할 수 없습니다.

## Claude Code 실제 호출과 어댑터 보완

2026-10-14에 Claude Code 2.1.296(Opus 5.5)으로 다른 책 지식 스킬을 실제 호출해 검토하고, 그 결과를 이 후속 스킬에 일반화했습니다. 후속 스킬의 전체 FLOW를 Claude Code에서 다시 수행한 시험은 아닙니다.

| 실제 관측 | 영향 | 보완 |
|---|---|---|
| Claude Code는 `Skill` 도구로 스킬을 불러올 때 SKILL.md를 Read로 읽지 않는다. 기존 어댑터는 `Skill` 도구를 막고 SKILL.md Read만 증거로 인정했다. | 시험 스킬로 기존 설정을 그대로 실행하자 slash 요청은 실제로 확장됐는데도 로드 증거가 없었다. 자연어 요청은 모델이 Glob으로 파일을 찾아 연 경우만 통과했다. | `Skill` 도구 허용. 성공한 `Skill` 결과 바로 다음의 합성 메시지가 격리 복사본 경로와 고정 SKILL.md 본문에 맞을 때만 SKILL.md read로 정규화하고 `native_skill_load`를 기록 |
| `-p` 모드의 `/<id>` 요청은 stream-json에 로드 이벤트를 남기지 않는다. | slash 요청으로는 자동 host-smoke의 로드를 증명할 수 없다. | host-smoke 입력에 스킬 이름을 넣도록 안내 |
| 보이는 스킬이 사용자 수준까지 합쳐 315개였다. | 다른 스킬이 섞이고 목록에서 설명이 생략될 수 있다. | `--setting-sources project`로 이 호출에서만 사용자 수준을 제외(시험 환경에서 20개로 줄어듦) |
| 인자를 넘긴 로드에서 SKILL.md 본문의 "$1,000"이 인자의 단어로 바뀌었다. `$ARGUMENTS`, `${CLAUDE_SKILL_DIR}`도 바뀌고 `` !`명령` ``은 셸 실행을 시도했다(권한 거부). | 금액 표기가 있는 책 스킬은 Claude에서 실제로 본문이 깨진다. 로드 증거도 맞지 않는다. | static-checks에 `claude-load-substitution` 경고, host-smoke는 호출 한도를 쓰기 전에 `claude-skill-substitution`으로 차단 |
| 답변 모델이 제작 프로젝트의 원문 PDF를 `pdftotext`로 열려다 권한 확인에 막혔다. 검색 몇 줄만 읽고 답하기도 했다. | 원문 의존·조건 누락 | 대상 SKILL.md의 답변 시 지침 점검, behavior-tests의 실제 호스트 실행과 추적 점검 추가 |
| 답변이 절 전체 범위로 인용했다. 스킬 정리를 저자의 말로, 저자의 절차를 스킬 양식으로 쓴 귀속 오류가 양쪽에 있었다. 판정자도 원문 없이 귀속을 잘못 판정했다. | 근거의 무게를 판단할 수 없음 | 문장 단위 위치와 쪽 대응표 기계 대조, 양방향 귀속 확인, 판정자에게 원문 쪽 제공 |

### 검증

- 단위 시험이 모두 통과했습니다. Claude 네이티브 로드 결속, 줄바꿈·BOM, 덧붙은 본문 거부, 치환 표기 사전 차단, run_state 재계산, 정적 경고 시험을 추가했습니다. 정적 검사기는 PyYAML·markdown-it-py가 있는 환경에서 실행했습니다.
- 보완한 어댑터로 시험 스킬을 CLI에서 실제 호출했습니다. record는 verdict `pass`, `loaded: true`, `native_skill_load: true`였고 proof는 격리 복사본의 SKILL.md였습니다. 같은 record를 run_state의 host-smoke 검증에 넣으면 통과하고, `native_skill_load`만 바꾼 record는 거부됩니다.
- 실제 로그 9개로 결속 조건을 재생했습니다. 정상 `Skill` 로드 5건은 인정했고, 상위 폴더에 같은 id 사본이 있을 때도 격리 복사본을 인정했습니다. 본문이 치환된 2건은 거부했습니다. 지식 스킬 검토 때의 로그는 호출 당시 버전의 SKILL.md와는 맞고 그 뒤 수정한 SKILL.md와는 맞지 않았습니다.

### 다른 책에서 다시 확인

교훈이 매매 책 하나에만 맞는지 보려고 게임 기획 책 지식 스킬(『몰입을 설계하는 게임 기획』)로 두 가지를 확인했습니다. 대상 스킬은 고치지 않았습니다.

- **격리 Claude CLI 3회:** 같은 격리 인자와 원문 이름의 미끼 파일을 두고 실행했습니다. 자연어 요청 2회는 모두 네이티브 `Skill` 로드가 증명됐고, slash 요청 1회는 로드 이벤트가 없었습니다. 답변은 "2–47쪽" 같은 절 범위로 인용했고, 한 답변은 수치의 정확한 쪽을 확인하지 못했다고 밝혔습니다. Grep으로 몇 줄만 보고 답한 경우도 있었습니다. 미끼 파일은 열지 않았습니다. 대신 그 스킬의 SKILL.md에 "재확인할 때는 원본 PDF를 읽는다"는 문구가 있었습니다.
- **후속 스킬 비교:** 같은 사전 점검·계획 요청을 이 책에 대해 수행하게 했습니다. 고정한 9개 항목에서 보완 후 9/9, 보완 전 2/9였습니다. 보완 후 답변은 위 문구, 이 책의 위치 형식(본문/PDF 쌍), 문장 단위 쪽 표기가 없는 절을 실제 파일과 맞게 짚었고, 매매 책 고유 점검을 끌어오지 않았습니다. 보완 전 답변의 문제 발견도 대체로 정확했으며, 점수 차이는 답변 시 지침·CLI 로그 점검·원문 분리 같은 절차에서 났습니다.

설정당 1회 실행이고, 판정 항목은 이번 교훈에서 나왔습니다. 다른 책으로 후속 FLOW 전체를 다시 수행한 것은 아닙니다.

### 한계
