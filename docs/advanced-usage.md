## 기존 검증 기록으로 시작하기

이전 실행 기록은 문제 후보와 회귀 사례의 출발점입니다. 이전의 “통과”를 이번 실행의 최종 통과로 그대로 사용하지 않습니다.

```text
$book-to-skill-followup
프로젝트 루트: /work/game-skill
대상 스킬: /work/game-skill/.agents/skills/game-design
원문: /library/game-design.pdf
기존 검증 기록: /work/game-skill/output/skill-review/latest/report.md

기존 기록의 결함은 회귀 사례로 보존하고, 원문 대조와 독립 시험을 새로 수행해줘.
```

**기대 결과:** 과거 결함을 오류 ID, 재현 입력, 필수 결과, 금지 결과로 정규화하고, 수정 전 증거를 지우지 않습니다.

**미정 사항:** 기존 기록이 어느 원문·스킬 버전을 기준으로 했는지는 해시로 확인합니다.

**검토 기준:** 같은 평가자 재생성과 새 독립 평가, 실제 도구 로그와 수동 읽기 목록을 한 종류의 증거로 합치지 않습니다.

## 여러 문서가 있는 프로젝트

프로젝트에 여러 스킬이 있어도 대상 스킬 하나만 선택합니다. 루트 README가 여러 스킬을 설명하면 기존 내용을 덮어쓰지 않고 대상 스킬의 상세 문서를 `docs/` 아래에 추가합니다.

```text
대상 스킬은 economy-design 하나다.
루트 README에는 combat-design과 economy-design이 함께 있으므로 기존 목차를 보존해줘.
economy-design의 설치·빠른 사용·고급 가이드는 docs/economy-design/에 추가해줘.
```

**기대 결과:** 현재 프로젝트 구조에 맞는 문서 경로와 링크가 생기고, 다른 스킬의 안내는 변경하지 않습니다.

**미정 사항:** 문서가 이미 해당 스킬 전용인지 확실하지 않으면 수정 전 구조를 기록합니다.

**검토 기준:** 링크·앵커 검사와 변경 전후 파일 목록 비교로 범위를 확인합니다.

## 출처 귀속 오류를 회귀 사례로 만들기

원문의 직접 원칙과 일반적인 설계·검증 지침이 섞이는 경우에 사용합니다.

```text
다음 스킬 답변은 데이터 행 의미와 중복 검증을 책의 직접 원칙처럼 서술한다.
원문에 직접 근거가 있는 부분, 스킬의 재구성, 검증 기반 적용 지침,
새 프로젝트 제안을 분리해줘. 직접 근거가 없으면 책의 주장으로 고치지 마.
```

**기대 결과:** 출처 층위별 근거 위치와 변경 제안이 남고, 불확실한 문장은 단정하지 않습니다.

**미정 사항:** 원문에 표현이 없는 일반 지침은 원문으로 소급하지 않습니다.

**검토 기준:** 최종 스킬과 예시 문서가 동일한 귀속 체계를 따릅니다.

## 확정 정책과 미정 정책을 분리한 QA

```text
메모에는 “동일 요청은 한 번만 보상 지급”이 확정돼 있다.
응답 실패, 재시도, 저장 시점은 미정이다.
확정된 중복 지급 금지의 필수 결과는 유지하고,
응답·복구 정책은 조건부 시나리오와 결정 질문으로 나눠 QA를 작성해줘.
```

**기대 결과:** 확정 정책은 필수 결과로, 미정 정책은 조건부 기대 결과와 결정 질문으로 나뉩니다.

**미정 사항:** 상충하는 UI·규칙이 있으면 하나의 합격 결과를 임의로 정하지 않고 모순과 수정안을 기록합니다.

**검토 기준:** 시나리오 계획과 실제 실행 결과를 구분해 표현합니다.

## 독립 행동 시험 설계

대표 시험은 세 유형을 포함합니다.

| 유형 | 요청 예 | 통과 기준 |
|---|---|---|
| 자료 선택·개념 확인 | 특정 장·개념의 근거와 적용 범위를 설명 | 관련 자료를 선택하고 출처 층위를 구분 |
| 실제 적용 | 기능·데이터·UX 명세를 작성 | 원문의 제약과 미정 정책을 보존 |
| 모순·미정 검토 | 규칙·UI·QA 메모의 충돌을 점검 | 모순, 영향, 수정안, 결정 질문을 분리 |

평가자에게는 요청, 대상 스킬, 작업에 필요한 최소 원자료만 제공합니다. 예상 답변·이전 결론·수정 방향을 전달하지 않습니다.

> [!TIP]
> 행동 시험이 실패한 경우에만 필요한 문서·스킬 문장을 최소 수정합니다. 예시 개수를 늘리거나 일반 규칙을 누적하는 방식으로 실패를 가리지 않습니다.

## 보강한 조건을 예시와 새 대화의 후속에 연결하기

원문 검수에서 조건·예외를 보완했지만 사용자 가이드에는 기존 요청만 남아 있을 때 사용합니다.

```text
$book-to-skill-followup 기존 전체 후속 실행을 보완해줘.
대상 지식 스킬·원문·허용 문서: [실제 경로]
원문 검수에서 보강한 조건: [원문 위치와 수정된 자료 위치]
기존 요청 ID·앵커·장르·가상 입력·확정/미정 정책·숫자를 유지해줘.
README의 문제별 안내와 예시의 산출물·확인 기준에 조건을 연결하고,
기존 맥락에 맞지 않는 조건만 별도 예시로 보완해줘.
후속은 실제 선택안, 조건 판정·예외·근거·미확인 사항을 받아
판정이 유지되거나 바뀌는 이유와 다음 확인 자료를 남기도록 해줘.
대표 연계를 새 대화에서도 시험하고 전체 문서 검토와 실행한 범위를 구분해줘.
```

**기대 결과:** 보강 사항별 README·예시·후속 연결표와 보존 확인, 실제 선행 결과로 채운 후속 입력, 별도 새 컨텍스트의 후속 결과입니다.

**미정 사항:** 없는 상태·시스템·가격·목표는 원문 기법 이름만으로 도입하지 않습니다. 실제 입력이 필요한 조건은 미확인으로 남깁니다.

**검토 기준:** 기존 맥락을 바꿔 예외를 억지로 넣지 않았는지, 부모 링크·제목·요청이 같은 선택안을 가리키는지, 수정 전 답변을 새 요청의 실행으로 소급하지 않았는지 확인합니다.

## 제작 도구 없이 책 지식만 배포하기

```text
$book-to-skill-followup [책 프로젝트·스킬·원문 경로]의 전체 후속을 완성해줘.
이 후속 도구는 별도 제작 작업 공간에서 사용하고 책 저장소에는 복사하지 마.
기존 로컬 설치가 있다면 지식 폴더 중첩·Git 추적·명시적 제외 상태를 확인해줘.
책 지식 전체와 필요한 별칭·사용 가이드가 배포 후보에 있는지 검토하고,
제작용 스킬·별칭·원문·실행 로그가 들어 있으면 허용 범위 안에서 제외해줘.
기존 검수 기록과 책 지식·예시는 보존하고 Git 작업 권한이 없으면 필요한 정리 범위를 알려줘.
```

**기대 결과:** 실제 배포 파일 목록과 혼입 검사, 제외한 제작물과 보존한 지식 자료의 구분입니다.

**검토 기준:** `.gitignore`만 추가하고 이미 추적된 파일이 빠졌다고 보고하지 않습니다. 원본 도구 자체의 설치·검사와 책 결과물 검사를 구분합니다. 임의의 아카이브가 Git 제외 패턴을 따른다고 가정하지 않습니다.
