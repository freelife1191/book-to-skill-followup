# 이력과 설계 근거

이 프로젝트는 책 기반 게임 시스템 기획 스킬의 변환 후 검수 경험에서 일반화한 흐름입니다. 원래 프로젝트와 책 파일은 이 프로젝트의 실행 의존성이나 배포 자료가 아닙니다.

---

## 일반화한 교훈

| 확인된 실패 유형 | 일반화한 후속 조치 |
|---|---|
| 책의 직접 설명과 실무 검증 지침이 섞임 | 출처 층위를 네 종류로 구분하고 원문 위치를 기록 |
| 미정 응답 정책 때문에 확정 규칙까지 흐려짐 | 필수 결과와 조건부 결과·결정 질문을 분리 |
| 데이터 행·키·중복 범위가 모호함 | 행 의미, 키, 업무상 중복 검증, 조회 단위를 함께 점검 |
| 동일 평가자의 재생성을 독립 재검증처럼 표현 | 증거 유형을 명확히 분리하고 새 독립 평가를 최종 근거로 요구 |
| 수동 읽기 기록의 경로 오탈자 | 원본을 보존하고 정정 기록·실제 도구 로그를 구분 |
| 문서·프롬프트 수정 뒤 이전 호스트 검사 재사용 | 고정 뒤에만 호스트를 한 번 호출하고 이후 변경 시 무효화 |
| 답변 모델이 제작 프로젝트의 원문을 찾아 열거나 검색 몇 줄만 읽고 답함 | 대상 SKILL.md의 답변 시 지침 점검과 실제 호스트 실행의 추적 점검 |
| 절 전체 범위 인용, 양방향 귀속 오류, 원문 없이 이뤄진 귀속 판정 | 문장 단위 위치와 쪽 대응 기계 대조, 원문의 해당 쪽으로 양방향 귀속 판정 |
| 이전 검수가 조건의 결합·강도·기준·시점 차이를 놓침 | 원문 검수 항목에 네 가지 차이를 명시 |
| Claude 어댑터가 `Skill` 도구 로드를 인식하지 못함 | 주입 본문을 고정 SKILL.md와 대조해 결속하고 사용자 수준 스킬을 호출에서 제외 |
| SKILL.md 본문의 `$1` 같은 표기를 Claude가 인자로 바꿔 씀 | 정적 경고와 host-smoke 사전 차단 |

이 내용은 모든 책의 실제 지식이나 모든 스킬의 요구 사항이 아닙니다. 검증 기록에서 드러난 운영·증거 관리 문제를 다루는 일반 지침입니다. 원문 탐색·위치·귀속·Claude 연동 항목은 2026-10-14 주식 시황 책의 Claude Code 검토에서 나왔고, 같은 날 게임 기획 책 한 권에서 절 범위 인용·부분 읽기·원본을 열라는 문구가 다시 확인됐습니다. 두 사례에서 나온 점검 항목이므로 대상 책에 맞는지 판단해 적용합니다.

## 도메인에 한정된 사례

게임 시스템 기획 사례에는 수량 스테퍼, 랜덤 상점, 자동 편성, 출석 보상처럼 데이터·UI·규칙·QA가 한 요청에 섞이는 상황이 있었습니다. 다음은 그 사례에만 해당합니다.

- 특정 게임 책의 장 수, 챕터 파일명, PDF 쪽수와 인쇄 쪽수의 오프셋
- 확률과 가중치, 자동 편성 우선순위, 보상 지급 규칙의 구체적 정책
- 게임 테이블의 행·키·중복 범위와 UI 상태 정의

후속 스킬은 이러한 구체 정책을 기본값으로 쓰지 않습니다. 다른 책·도메인에서는 원문과 대상 스킬의 실제 구조를 먼저 인벤토리로 확인합니다.
