# 문제 해결

## Claude Code OAuth 만료

`OAuth session expired and could not be refreshed`는 스킬 미발견과 다른 인증 차단입니다. init에서 스킬·역할을 발견했더라도 실제 답변과 성공 종료가 없으면 행동 시험은 통과하지 못합니다. 인증 오류 원문과 종료 결과를 보존하고, 사용자가 건너뛰기로 정하면 해당 호스트를 추가 호출하지 않습니다. 비밀번호·토큰을 검증 기록이나 프롬프트에 넣지 않습니다.

## Antigravity 종료는 성공인데 읽기 근거가 없음

AGY의 `result.status: SUCCESS`나 exit 0은 모든 도구의 성공을 보장하지 않습니다. 원래 로그의 view_file ACTIVE/DONE 쌍, AbsolutePath, 출력과 tool_info.error를 확인합니다. 승인 거부·오류·완료 이벤트 부재·다른 conversation의 결과는 유효한 읽기 근거로 승격하지 않습니다. [실제 로그 계약](../.agents/skills/book-to-skill-followup/references/host-adapters.md#antigravity-네이티브-실행-로그)을 참고하세요.

## 입력 경로가 맞지 않음

`FOLLOWUP_SKILL_DIR`은 제작 작업 공간의 도구 위치이며 `--project`는 책 결과물의 위치입니다. 두 경로를 같은 것으로 추측해 도구를 책 저장소에 복사하지 않습니다.

| 증상 | 확인 | 처리 |
|---|---|---|
| 대상 스킬이 프로젝트 밖에 있음 | `--project`와 `--skill`의 실제 경로 관계 | 대상 하나와 허용 쓰기 경계를 다시 지정하고 새 실행 시작 |
| 원문을 열 수 없음 | 경로·읽기 권한·원문 동일성 | 추측으로 대체하지 않고 `blocked` 기록 |
| 원문이 여러 개임 | 제목·판본·해시·기존 메타데이터 | 사용자가 대상을 정할 때까지 중단 |

> [!IMPORTANT]
> 원문이 없거나 동일성을 확인할 수 없으면 기존 추출물을 원문처럼 확정하지 않습니다. 가능한 검수 범위와 제한을 명시합니다.

## 도구·검사기가 실행되지 않음

`nested-followup-tool`, `tracked-followup-tool`, `unexcluded-followup-tool`은 생성된 책에 제작 도구가 섞였거나 제외되지 않았다는 뜻입니다. `unmanaged-followup-tool`은 Git 없는 프로젝트의 도구를 배포 제외됐다고 확인할 수 없다는 뜻입니다. `git-status-unavailable`이면 Git 상태 확인 오류를 먼저 해결하며 제외 통과로 처리하지 않습니다. 정리는 허용된 경로·Git 작업 범위에서 하고, 원본 제작 도구나 전역 설치를 자동 삭제하지 않습니다. [배포 분리](../.agents/skills/book-to-skill-followup/references/packaging.md)를 따릅니다.

`run_state.py`는 Python 표준 라이브러리만 사용합니다. `check_package.py`는 **Python 3.11 이상**, `PyYAML`, `markdown-it-py`가 필요합니다. 이 프로젝트를 제작·검수한 현재 환경에서는 두 파서를 확인했지만, 설치 대상 환경까지 자동으로 준비하지는 않습니다.

| 상황 | 처리 |
|---|---|
| Python 버전이 부족함 | 버전과 요구 조건을 기록하고 검사 단계는 차단 |
| YAML·Markdown 파서가 없음 | `pip` 자동 설치를 하지 않음. 환경에 이미 준비된 도구를 사용하거나 차단 기록 |
| 검사 출력 경로가 실행 폴더 밖임 | 실행 폴더 아래의 역할별 경로로 바꿔 다시 실행 |
| 링크·앵커 검사 실패 | 실제 대상과 앵커를 수정한 뒤 영향받은 정적 검사부터 재개 |

동일한 일반 도구 실패는 한 번만 재시도합니다. 원인 없이 반복 호출하지 않습니다.

## 독립성·기록 문제가 생김

| 문제 | 처리 |
|---|---|
| 평가자에게 이전 결론이 전달됨 | 시험을 독립 평가로 부르지 않고 입력 범위를 기록. 필요하면 새 컨텍스트에서 다시 평가 |
| 읽기 목록의 경로가 존재하지 않음 | 원본 기록을 보존하고 정정 기록을 별도로 남김. 실제 도구 로그로 소급하지 않음 |
| 같은 평가자의 재생성만 있음 | 유용한 보완 확인으로 기록하고 새 독립 평가를 추가 |
| 초기 실패를 삭제하고 싶음 | 삭제하지 않음. 실패·보완·재검증의 관계를 기록 |

## 호스트 검사가 막힘

사용 중인 호스트의 인증, CLI, GUI, 권한 또는 실행 환경이 없어 실제 호출을 할 수 없으면 호스트 검사는 `blocked`입니다. 다른 호스트의 정적 프로필 검사로 대체해 완료를 주장하지 않습니다.

호스트 호출을 시도할 수 있는 환경이 갖춰지면 **새 실행**에서 고정·호스트 검사·최종 검토를 수행합니다. 최종 호출은 한 실행에 한 번만 하며, 실패 뒤 무의미하게 반복하지 않습니다.

> [!WARNING]
> 최종 호출에서 새로운 결함이 나오면 호출 로그는 보존하지만 완료 판정은 내리지 않습니다. 다음 실행에서 수정하고 처음부터 필요한 게이트를 다시 통과합니다.
